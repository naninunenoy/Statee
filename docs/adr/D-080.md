# D-080 ボクセル生成ツール voxcee を tools/voxcee に置く

## 決定

ボクセルをテキスト定義(`.voxel.txt`: パレット + 水平スライス)から
GLB に変換するコンソールアプリ **voxcee** を `tools/voxcee/` に新設する。スコープは
「テキスト → GLB 変換器」に留める(アニメーション・複数モデル結合・Godot シーン出力は必要になるまで作らない)。

- 形式: `palette:` 節に「文字 = #RRGGBB(AA)」、`layers:` 節に Y 昇順の水平スライス。
  空行でスライスを区切る。各スライス行は Z 走査、文字は X
- メッシュ: 固体ボクセルの外側面だけを quad 化(隣接固体との面はカリング)
- GLB: 依存なしの自前 glTF 2.0 バイナリ(POSITION / NORMAL / COLOR_0 / indices)
- ボクセル定義本体は各ゲーム側に置き、ツールはゲーム非依存を保つ

## 背景

- dotee(D-070)と同様、AI エージェントは 3D メッシュを直接 sculpt できないが、
  ボクセルは「色付き 3 次元配列」なのでテキストで表現できる
- Godot 4 は GLB をネイティブ import でき、1 メッシュ資産として扱える
- MagicaVoxel `.vox` 等のバイナリ形式は取り込まない。dotee と同じく
  テキスト定義に一本化し、ツールの保守コストを抑える

## トレードオフ

- 面カリングは quad 単位のみ(greedy meshing なし)。ボクセル数が増えると GLB が大きくなる
- 自前 GLB エンコーダは PBR マテリアル・テクスチャ・スキニング非対応(頂点色のみ)
- slnx が 1 本増え、`tools/build-all.ps1` の対象になる(-Depth 2 の範囲内)
- MagicaVoxel 資産は手動で `.voxel.txt` に起こすか、別経路で GLB 化する前提
