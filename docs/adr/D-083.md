# D-083 ログ実装は PC=ZLogger、Web=GD.Print(dn2cpp)

## 決定

ゲームが触るログ API はこれまで通り `ILogger` / `StateeLogging.CreateLoggerFactory`。
**実装(シンク)だけ**をビルドで差し替える。

| 対象 | 実装 | 含めないもの |
|---|---|---|
| PC(エディタ / デスクトップ出力) | `LogBuffer` + ZLogger コンソール(D-008) | `LoggerFactory.Create`(MEL DI) |
| Web(`GodotTargetPlatform=web` / `GODOT_WEB`) | `LogBuffer` + `GD.Print`(ブラウザコンソールへ出る) | ZLogger パッケージ、MEL の `LoggerFactory.Create` |

切替は実行時 `if` ではなく **ビルド**(csproj の `Compile Remove` + 条件付き `PackageReference`)。
dn2cpp は `_Ready` から届く IL を全部辿るため、Web の DLL に ZLogger / `SetMinimumLevel` が残ると変換が落ちる。

複数シンクへの分配は Godot 非依存の `TeeLoggerFactory`(Statee.Core)が担う。

## 背景

dn2cpp Web エクスポートで、起動経路の失敗は次の順で移った。

1. ZLogger 補間(MagicalBox) → `Enum.GetEnumValuesAndNames`(D-082)
2. `LoggerFactory.Create` + `SetMinimumLevel` → `ServiceDescriptor.ToString` →
   `StackTrace.get_IsSupported`(intrinsic 未実装)

どちらも「PC 用のログ実装が Web の到達グラフに残っている」ことが原因。
Web では Statee の TCP 入口も無い(D-065)ので、ZLogger の UTF-8 補間も DI も不要。
`GD.Print` は Web ではブラウザのコンソールに出る。

`LoggerFactory.Create(Action<ILoggingBuilder>)` は内部で DI を組む。
PC 側も `new ZLoggerConsoleLoggerProvider(...)` を `TeeLoggerFactory` に渡すだけにし、
MEL DI を起動経路から外す。

## トレードオフ

- (+) Web の IL から MagicalBox と `StackTrace.IsSupported` を外せる
- (+) ゲーム側の `_logger.LogInformation` はそのまま
- (+) PC の ZLogger / `logs` コマンド用バッファは維持(D-008)
- (−) Web では ZLog 補間(`ZLogInformation($"...")`)をゲームが直接呼ぶと、
      ZLogger 参照が復活して変換が再び落ちる。Godot 層は `ILogger` だけを使う
- (−) `GodotTargetPlatform` が `web` にならない publish だと切替が効かない
      (dn2cpp はホスト RID で publish するが、`GodotTargetPlatform=web` は渡す)

## 状態

採用。D-082 の「起動経路で ZLog 補間を避ける」は、Web では本決定で不要になる。
PC の Godot 層に残る ZLog 補間は、Web ビルドに含まれなければ妨げない。
