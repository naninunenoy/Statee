# D-078: 検証用 State は敵とステージ形状を実体単位で公開する

## 決定

- `game/messbreak` の敵は **`Enemies` 配列**(`{Id, Kind, Hp, X, Y, DebuffTicks}`)として
  生存している全個体を公開する。`Id` はフレームを跨いで安定(GUIDELINE 3.4 / D-006)、
  撃破された敵は配列から消える
- ステージ形状は **`StageRows`**(1行1文字列。`'#'` が壁)と **`TileSize`** として公開する
- 単数フィールド `MobHp` / `MobDebuffTicks` / `BossHp` / `BossX` / `BossY` /
  `BossDebuffTicks` は撤去する(`Enemies` に包含されるため)

## 背景

- ステージ定義(ASCII マップ。DESIGN.md)の導入で雑魚を複数配置できるようになったが、
  State 側は `EnemyOf(EnemyKind.Mob)` の1体分しか公開しておらず、
  仕様である「**全滅でエリア制圧**」を State から検証できなかった。
  「検証に必要な情報を全公開する」(MessBreak.Godot/CLAUDE.md)が守られていない状態だった
- 壁も公開されていなかったため、壁との位置関係(通路を抜けたか・弾が壁で消えたか)を
  State だけでアサートできなかった
- 同型の問題は `samples/RogueGame` が `Enemies`(`EnemyEntry`)+ `Map` 行文字列で
  解いており、TOON もこの形をテーブルとして表示できる。同じ形を採る

## トレードオフ

- 特定の敵1体を見るには配列から `Kind` や `Id` で引く必要があり、単一値の assert より一手増える。
  「雑魚が全滅したか」のような**集合に対する問い**が主用途なので、この方向を選んだ
- 毎 tick 配列を割り当てる(敵は数体のため許容。`StageRows` は不変参照の受け渡しで複製しない)
- 撃破された敵は配列から消えるため「初期の雑魚数」は State から直接読めない
  (`StageRows` の `'M'` を数えれば導出できる)

## 状態

採用。headless E2E(`--frozen` + `tick`)で確認済み:

- tick 0 で `StageRows[9]` が `Stages.Room1Text` と一致、`TileSize: 40`、
  `Enemies[1]: 1,Mob,3,500,100,0`(`'M'` セル col 12 / row 2 の中心と一致)
- 雑魚へ3発命中させると `Hp` が 3 → 2 → 1 と減り、撃破と同時に `Enemies[0]` かつ
  `ZoneCaptured: true` へ遷移
- タレット設置 → アトラクトで `Enemies[1]: 2,Boss,20,500,220,0` が出現(`Id` は雑魚と重複しない)。
  デバッファーのスキルで同エントリの `DebuffTicks` が 295 になり、
  撤去した `BossHp` / `BossX` / `BossY` / `BossDebuffTicks` が代替できていることを確認
