# D-079: 演出タイマーは論理 tick に同期し、敵に紐づく演出は対象ごとに持つ

## 決定

- ヒット演出のタイマー(被弾フラッシュ・ヒットマーカー・スキル爆発リング)は physics フレーム
  ではなく **論理 tick 1 回ごと**に減らす。自動 tick と `tick` コマンド(D-072)の両方から
  同じ処理(`AdvanceEffectTimers`)を呼ぶ
- 敵に紐づく演出状態は **対象ごとに持つ**。被弾フラッシュは敵 Id をキーにした辞書とし、
  画面で 1 つの変数を共有しない
- ロジックは敵に紐づく出来事に対象の Id を載せる(`BattleEvent.EnemyId`。
  EnemyHit / EnemyKilled / EnemyDebuffed)。Godot 層は「どの敵の出来事か」を
  State の差分から推測しない(USING.md の禁止事項)
- **ヒットストップは例外**で physics フレーム基準のまま。論理を止める側の演出なので
  論理 tick に同期させると自分で自分を進められなくなる

## 背景

- 雑魚が 1 体だけの頃は露見しなかったが、既定ウィンドウの拡大と Room1 の雑魚 3 体化で
  「1 体に命中すると**見えている全敵が白く光る**」ことが判明した。原因は被弾フラッシュの
  残フレーム数を画面でひとつ共有し、描画ループが全敵に適用していたこと。
  ロジックのダメージ処理は正しく 1 体だけを削っていた(State の Enemies で確認済み)
- `BattleEvent` は `(Kind, Pos)` だけで、Pos は弾の命中位置なので敵と対応付けられなかった。
  HP の差分から光らせる実装なら logic 変更なしで済むが、
  「効果音・エフェクトの発火を状態の差分から推測させない」(USING.md)に反するため採らない
- 演出タイマーが physics フレーム基準だったため、**freeze 中も実時間で 4 フレーム
  (約 67ms)で消え**、この種の見た目バグをスクリーンショットで検証できなかった
  (CLI の往復は 1 秒近い)。論理 tick 同期にすると `freeze` + `tick` で命中フレームを
  狙って撮れるようになり、GUIDELINE §1 の「同レイヤーの証人」が成立する

## トレードオフ

- 演出タイマーが論理 tick 基準になるため、ヒットストップ中(論理が止まる 2〜6 フレーム)は
  フラッシュも止まる。演出としては「止まった絵のまま白い」ので違和感はない
- 敵 Id ごとの辞書は毎 tick キーの列挙で 1 回配列を作る(敵は数体なので許容)
- 撃破された敵の Id は辞書に残り得るが、描画は生存中の敵しか引かないため見た目に影響はない
  (次の減衰で消える)

## 状態

採用。headless ではなく窓あり + `--frozen` + `tick` の E2E で確認済み:

- 雑魚 3 体のうち Id 2 に 1 発命中させた瞬間のスクリーンショットで、
  **被弾した 1 体だけが純白**、他の 1 体は通常色(紫)のまま
- そこから 4 tick 進めるとフラッシュが消え、HP 1/3 に応じた暗い紫に戻る
  (論理 tick に同期して減衰することの確認)
- ロジック側は 106 テスト緑。`EnemyHit` が被弾した 1 体の Id だけを持つことを
  複数雑魚のテストで固定した
