# D-084 Web ビルドでは StandardCommands を起動経路に載せない

## 決定

`StandardCommands.Register`(ping / key / screenshot / quit / `system/identity`)は
**PC のみ**。Web(`GodotTargetPlatform=web`)では実装ファイルを `Compile Remove` し、
`partial void RegisterCore` の呼び出し自体をコンパイラが消す(D-065 と同じ型)。

PC の仕様(D-047 / D-075)は変えない。ゲーム側の `StandardCommands.Register(...)` 呼び出しは
Web でも残してよい(空振りになる)。

## 背景

dn2cpp Web エクスポートで、ログ実装を差し替えたあと(D-083)の失敗は次の順で移った。

1. `IdentityStateProvider` → `Process.GetCurrentProcess`(未対応 intrinsic の巨大グラフ)
2. `screenshot` の `Directory.CreateDirectory` → Encoding / `Godot.Colors` / Arch 経由で
   また未対応 intrinsic(`Int32.Equals(Object)` など)

どちらも TCP 経由の検証用コードが、プレイ用 Web の `_Ready` 到達グラフに残っていることが原因。
Web には Statee の TCP 入口が無い(D-065)。標準コマンドも identity も、Web のプレイ用
ビルドでは使わない。

1 件ずつ外すより、検証用の一括登録ごとビルドから落とす。

## トレードオフ

- (+) Web の到達グラフから `Process.*` と `Directory.CreateDirectory` をまとめて外せる
- (+) PC の ping / key / screenshot / quit / identity は維持する
- (−) Web では標準コマンドも `system/identity` も無い。TCP も無いので検証シナリオは
      もともと動かない
- (−) ゲーム固有コマンド(`start` / `drop` 等)は `StartStatee` に残る。次の未対応
      intrinsic を引く可能性は残る

## 状態

採用。Suika の dn2cpp Web エクスポートで、identity の `Process` と screenshot の
`Directory.CreateDirectory` は消えた。次の失敗はゲーム本体。

表示上のチェーンは
`SetOverflowing` → Arch `World.Remove` → `FruitId.Equals` → `Int32.Equals(Object)`
だが、**`World.Remove` が `FruitId.Equals` を呼んでいるわけではない**。

- 実行時の実呼び出しは `_PhysicsProcess` → `SetOverflowing` → `_world.Remove<OverflowComponent>`
- `Signature.Remove` が `Enumerable.ToArray` を使い、ArrayPool / `Godot.Colors` などへ
  トリムが爆発する(表示チェーンの中間は実行時の呼び出しではない)
- 停止点は UnitGenerator が生成した `FruitId.Equals(object)` のフォールバック
  `value.Equals(obj)` → `Int32.Equals(object)`。dn2cpp は CoreLib を IL から写さず、
  この intrinsic がまだ無い
