# D-084 Web ビルドでは system/identity を起動経路に載せない

## 決定

`StandardCommands.Register` の `system/identity` 登録(`IdentityStateProvider`)は
**PC のみ**。Web(`GodotTargetPlatform=web`)では `partial void RegisterIdentity` の
実装ファイルを `Compile Remove` し、呼び出し自体をコンパイラが消す(D-065 と同じ型)。

PC の仕様(D-075)は変えない。

## 背景

dn2cpp Web エクスポートで、ログ実装を差し替えたあと(D-083)の次の失敗は
`IdentityStateProvider` のコンストラクタが `Process.GetCurrentProcess` を呼び、
未対応 intrinsic(`Int32.Equals(Object)` など)を巨大な到達グラフ経由で引くことだった。

Web には Statee の TCP 入口が無い(D-065)。identity は「CLI が古いバイナリに
繋いでいないか」を検証するための State なので、Web のプレイ用ビルドでは使わない。

## トレードオフ

- (+) Web の到達グラフから `Process.*` を外せる
- (+) PC の identity 確認は維持する
- (−) Web では `system/identity` が無い。TCP も無いので検証シナリオはもともと動かない
- (−) `screenshot` の `Directory.*` など、Web でも残る標準コマンドが次の未対応
      intrinsic を引く可能性は残る
