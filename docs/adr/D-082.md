# D-082 `_Ready` 起動経路では ZLog 補間を使わない(dn2cpp Web エクスポート)

## 決定

Web に出すゲームでは、`_Ready` から到達する経路で
ZLogger の補間文字列(`ZLogInformation($"...")` 等)を使わない。
ログは `ILogger.LogInformation("...", args)`(MEL のテンプレート文字列)にする。

対象:

- Godot 層の `_Ready` 本体、そこに書く購読ラムダ、`StartStatee` のコマンド登録
- `_Ready` から直接呼ばれるメソッド
- `Statee.Godot.StandardCommands.Register`(全ゲームの `StartStatee` から呼ばれる)

含めない:

- 上記以外の Godot 層。ZLogger と `$"..."` 必須(CS9205)を維持する(D-008)
- その穴に enum を置くなら `{kind.ToString()}`。番号でよければ `{(int)kind}`
- `src/`(Core / Remote / MCP / CLI)。ゲームの Web 事情を持ち込まない(D-013)
- `Main.StateeServer.cs`(ExportRelease から消える。D-065)

`StandardCommands` はスイカ固有ではなく、全ゲームの起動経路そのものなので D-013 の対象外。

## 背景

dn2cpp は `System.Enum::GetEnumValuesAndNames`(InternalCall)をまだ変換できない。
ZLogger の UTF-8 補間ハンドラ(MagicalBox)は、穴の実行時型が `string` でも、
`$"..."` 自体が enum 書式を型グラフに残す。
MEL の `LogInformation` は補間ハンドラを生成しないので CS9205 の対象外でもあり、
起動経路から MagicalBox を外せる。

Linux エディタ zip で Suika を試したとき、失敗チェーンは次の順で移った。

1. `SuikaGame.Main._Ready` → MagicalBox
2. `StartStatee` のコマンドラムダ → MagicalBox
3. `Statee.Godot.StandardCommands.Register` → MagicalBox

3 を外したあと MagicalBox は出なくなった。次の失敗は別件で、
`StateeLogging.CreateLoggerFactory` → `SetMinimumLevel` →
`ServiceDescriptor.ToString` → `StackTrace.get_IsSupported`(intrinsic 未実装)。
ZLog 補間の範囲外。

## トレードオフ

- (+) `_Ready` 起動経路から MagicalBox を外し、Web エクスポートの失敗チェーンを切る
- (+) ZLogger は起動経路の外と `src/` で維持する(D-008)
- (−) 起動経路だけログ API が分かれる。忘れやすい
- (−) MagicalBox を外しても、`CreateLoggerFactory` が DI 経由で `StackTrace` を引き、Web エクスポートはまだ落ちる
- (−) dn2cpp が enum 書式をサポートしたら、ZLog 側の制約は不要になる

## 状態

改訂。Web の起動経路から MagicalBox を外す手段は D-083(ログ実装のビルド差替)に移した。
PC の Godot 層に ZLog 補間が残っていても、Web ビルドに ZLogger が含まれなければ妨げない。
