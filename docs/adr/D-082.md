# D-082 C# Godot の Web 出力は godot-dn2cpp を使い、プレビルドを優先する

## 決定

C# プロジェクトの Web エクスポートは、公式 `GODOT_BIN` ではなく
[godot-dn2cpp](https://github.com/takuma-komatsu/godot-dn2cpp) を使う。

- **Windows x86_64 / macOS arm64** は GitHub Releases のプレビルドを取得する。
  取得・展開・ハッシュ照合・プリセット生成・headless export は
  `tools/export-web.sh` / `tools/export-web.ps1` が行う
- **プレビルドの無いホスト(Linux 等)** は dn2cpp の
  `gates/setup-godot-fork.sh` + `setup-godot-fork-web.sh` で自前ビルドする。
  godot-dn2cpp の scons だけでは足りない(toolchain を `bin/GodotSharp/Dn2Cpp/` に同梱する必要がある)。
  コピー可能なコマンドは `tools/export-web.sh --print-build-fork`
- パスは環境変数 `GODOT_DN2CPP_BIN` と `GODOT_DN2CPP_WEB_TEMPLATE`。
  未設定ならスクリプトがキャッシュへ落として埋める(プレビルドがあるホスト)。
  `GODOT_BIN` とは混ぜない。実行ファイルだけをコピーしない
- リリースと自前ビルドのコミットは `tools/godot-dn2cpp.pin` でピン留めする。
  ABI が 4.7.1-stable 固定のため latest は追わない
- エージェント手順の正本は `/export-web` skill(`.claude/skills/export-web/`)
- 完了シグナルは dn2cpp の export ログ + `index.html` / `.wasm` / `.pck`。
  Godot の exit 0 も Statee の ping も使わない
- 自前ビルドの Web テンプレートは同じ emcc で焼いたものだけを使う。
  Releases の zip と混ぜない

## 背景

公式 Godot 4 は C# を Web に出せない。dn2cpp は IL を C++ へトランスパイルし、
フォークエディタがそれを WASM side module としてリンクする。エディタ利用ガイドは
取得を人手に任せているが、0環境のエージェントが同じ手順を毎回間違える
(`GODOT_BIN` 流用、zip 展開、Linux でプレビルドを探す、scons だけで終わる)ため、
取得と自前ビルドの入口をスクリプト / skill に閉じる。

`dist/` に `package-editor-linux.sh` は無く、Linux は自前ビルドが本線
(dn2cpp `docs/EDITOR-EXPORT-DESIGN.md`)。

Statee の TCP 待ち受けはブラウザに存在せず、ExportRelease では D-065 により
ビルドから落ちる。Web 出力を `/verify` の延長にすると緑が嘘になる。

## トレードオフ

- (+) 0環境でも Releases の URL とピンだけで(対応ホストなら)資材が揃う
- (+) `GODOT_BIN` と分離するので、日常の headless 検証と出荷経路が混線しない
- (+) Linux でも同じ変数でエクスポートできる(ビルドは重いが経路は一本)
- (−) プレビルドは Windows x86_64 と macOS arm64 のみ
- (−) エディタ zip は数百 MB。自前ビルドは数十分〜数時間 + Godot のコンパイル依存
- (−) このリポジトリのゲームは dn2cpp Web 未検証。skill の完了は
  「ブラウザで遊べた」ではなく「エクスポートがログ上成功し HTTP 配信できる」
