# D-082 Godot 層の `_Ready` では ZLog 補間を使わない(dn2cpp Web エクスポート)

## 決定

Web に出すゲームの **Godot 層 `_Ready`**(そこに書く購読ラムダを含む)では、
ZLogger の補間文字列(`ZLogInformation($"...")` 等)を使わない。
起動ログは `ILogger.LogInformation("...", args)`(MEL のテンプレート文字列)にする。

- `_Ready` 以外の Godot 層では ZLogger を維持する(D-008)。`$"..."` 必須(CS9205)も維持する
- その穴に enum を置くなら `{kind.ToString()}`。番号でよければ `{(int)kind}`
- フレームワーク(`src/` / `libs/Statee.Godot`)には持ち込まない(D-013)
- `Main.StateeServer.cs` は ExportRelease から消えるので対象外(D-065)

## 背景

dn2cpp は `System.Enum::GetEnumValuesAndNames`(InternalCall)をまだ変換できない。
ZLogger の UTF-8 補間ハンドラ(MagicalBox)は、穴の実行時型が `string` でも、
補間ハンドラの型グラフに enum 書式が残るとその InternalCall に到達する。

Linux エディタ zip で Suika を試したとき、
`ZLogInformation($"... next={_logic.PeekNext()}")` も
`{PeekNext().ToString()}` も失敗チェーンは
`SuikaGame.Main._Ready` → `ZLogInformation` → MagicalBox のままだった。
穴を `ToString()` にしただけでは足りない。

MEL の `LogInformation` は補間ハンドラを生成しないので CS9205 の対象外でもあり、
`_Ready` の起動経路から MagicalBox を外せる。

## トレードオフ

- (+) `_Ready` から MagicalBox を外し、Web エクスポートの失敗チェーンを切る
- (+) ZLogger は `_Ready` 以外で維持する(D-008)
- (−) `_Ready` だけログ API が分かれる。忘れやすい
- (−) `_Ready` から呼ばれる `StartStatee` などに ZLog 補間が残ると、次の失敗チェーンになりうる
- (−) dn2cpp が enum 書式をサポートしたら、この制約は不要になる

## 状態
