# D-082 Godot 層の `_Ready` 起動経路では ZLog 補間を使わない(dn2cpp Web エクスポート)

## 決定

Web に出すゲームの **Godot 層**で、`_Ready` から到達する経路では
ZLogger の補間文字列(`ZLogInformation($"...")` 等)を使わない。
対象は `_Ready` 本体、そこに書く購読ラムダ、`StartStatee` のコマンド登録、
`_Ready` から直接呼ばれるメソッド。
ログは `ILogger.LogInformation("...", args)`(MEL のテンプレート文字列)にする。

- 上記以外の Godot 層では ZLogger を維持する(D-008)。`$"..."` 必須(CS9205)も維持する
- その穴に enum を置くなら `{kind.ToString()}`。番号でよければ `{(int)kind}`
- フレームワーク(`src/` / `libs/Statee.Godot`)には持ち込まない(D-013)
- `Main.StateeServer.cs` は ExportRelease から消えるので対象外(D-065)

## 背景

dn2cpp は `System.Enum::GetEnumValuesAndNames`(InternalCall)をまだ変換できない。
ZLogger の UTF-8 補間ハンドラ(MagicalBox)は、穴の実行時型が `string` でも、
補間ハンドラの型グラフに enum 書式が残るとその InternalCall に到達する。
穴の有無も問わない。`$"..."` 自体が MagicalBox を引く。

Linux エディタ zip で Suika を試したとき、失敗チェーンは次の順で移った。

1. `SuikaGame.Main._Ready` → `ZLogInformation` → MagicalBox
   (`{PeekNext()}` も `{PeekNext().ToString()}` も同じ)
2. `_Ready` の ZLog を MEL にしたあと:
   `SuikaGame.Main._Ready` → `StartStatee` → コマンドラムダ → MagicalBox

MEL の `LogInformation` は補間ハンドラを生成しないので CS9205 の対象外でもあり、
起動経路から MagicalBox を外せる。

## トレードオフ

- (+) `_Ready` 起動経路から MagicalBox を外し、Web エクスポートの失敗チェーンを切る
- (+) ZLogger は起動経路の外で維持する(D-008)
- (−) `_Ready` 配下だけログ API が分かれる。忘れやすい
- (−) Godot の他エントリ(`_UnhandledInput` 等)に ZLog 補間が残ると、次の失敗チェーンになりうる
- (−) dn2cpp が enum 書式をサポートしたら、この制約は不要になる

## 状態

採用。
