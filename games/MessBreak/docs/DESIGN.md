# MessBreak 企画・設計

MessBreak 固有の企画・設計・開発記録はこの `games/MessBreak/docs/` に置く。
Statee(フレームワーク)側の `docs/adr/` には持ち込まない。
Statee の ADR に書くのは、`src/` や repo 構成に波及する決定だけ。

## コンセプト

- **3D TPS(サードパーソンシューター)・リアルタイム戦闘**のダンジョンアクション
- **移動とエイムの独立+スキル主体、射撃は繋ぎ**。
  人間操作はマウスルック(エイム)+カメラ相対 WASD。エージェントの `tick` は
  ワールド絶対の left/right/up/down と aimx/aimy のまま(検証経路を壊さない)。
  倒す主役はクールダウン制のスキルとその組み合わせで、通常射撃は低ダメージの繋ぎ
- 敵は物量(バンサバ型)ではなく、少数の敵と準備・配置の設計で面白さを作る
- **一言でいうと: 防衛線を築きつつ、キャラを切り替えて自ら前線を張る 3D TPS**
  (縦切り3の方向決めを 3D 見た目へ移植)
- **論理は完全 2D 座標のまま**(X,Y)。Godot 層だけ Logic(X,Y) → World(X, 0, Y) に写す。
  当たり判定・壁スライド・敵 AI は純 C# の 2D のままテスト可能
- 見た目のモデルは **voxcee**(D-080)で `art/*.voxel.txt` → GLB。dotee スプライトは
  2D 時代の資産として残すが、実行時は GLB を使う
- キャラクター3人を切り替えて戦う。3人とも 18 歳の美少女:
  - アタッカー
  - バッファー(ヒーラー)
  - デバッファー

  キャラ切り替え=スキルセット切り替え。切り替えを挟むスキルコンボ
  (例: デバッファーでデバフ → アタッカーの大技を重ねる)が爽快感の中心

## 名前

- タイトルは **MessBreak**(表記はキャメルケースで統一)。
  「Mess(混沌・敵の群れ)を Break(打ち破る)」
- スラング上の問題・既存タイトルとの衝突がないことは確認済み(2026-07)。
  近縁名として Steam の「MESS」「Mecha BREAK」が存在する点のみ留意

## 開発方針

- 境界の掟(docs/USING.md)に従い、ルール・移動・当たり判定・敵 AI は
  `MessBreak.Logic`(純C#)に置き、xUnit + Shouldly でテストする。
  Godot 層は描画・入力・Statee 配線のみ
- 物理・衝突は Godot 物理に頼らず、Logic 層の自前判定(円・矩形)で行う
- 乱数は seed 注入、進行は tick 駆動で決定的に保つ
- ゲームバランスに関わる数値(速度・HP・攻撃力・部屋サイズ等)は
  ハードコードせず Logic 層の設定オブジェクト(BattleConfig / CharacterConfig)に集約する

## ゲームの枠(縦切り3の方向決め、2026-07-18)

「こういうゲームね」の一言を作るための方向決め。参照した先達は
陣取り+設置系(部屋を制圧すると設置権を得る構造)と、ボス戦前の準備が勝敗を
決める文化(設置物は守るためでなく**強敵を倒すため**の攻めの道具)。
プレイヤーの好みは「準備・編成・組み合わせの設計が答え合わせで報われる」タイプの
面白さであり、リアルタイムの操作精度をゲームの中心に置かない。
キャラ切り替え+スキルコンボは「仕込んだシナジーを現場で発火させるボタン」として核に残す。

## 現在の仕様

### ミッションループ(縦切り3-1、2026-07-18)

「小部屋1つ制圧 → 雑魚を倒して設置スロット解放 → タレットを置く →
出現ポイントをアトラクトして強敵出現 → 射撃+スキルコンボ+タレットで撃破」:

- 敵は **Enemy エンティティ(Mob / Boss)**。エイムアシスト・デバフ・スキル範囲は
  敵単位で効く(デバフは敵ごとに独立保持)
- **制圧**: 雑魚(HP 3 = アタッカースキル一撃)を**全滅**させると ZoneCaptured、スロット解放。
  Room1 は敵エリアに3体を散らして配置している(最近接ペアは 1 発のスキルで巻き込める間隔)
- **設置**: タレットは射程 160 内の最寄りの敵をクールダウン 30 tick ごとに自動射撃。
  タレット弾(Bullet.FromTurret)はプレイヤーの命中統計に混ぜない(デバフ倍率は乗る)
- **アトラクト**: 強敵(HP 20)が出現し、プレイヤーを追跡(接触距離で停止)。一度きり。
  強敵の攻撃は未実装(ループの成立検証に絞った)。プレイヤー HP は最小実装のみ
  (PlayerMaxHp=10、減らす手段が無いので常に満タン。UI 表示のために先行導入)
- **強敵撃破で MissionCleared**。HUD に進行ガイドを表示
- **Interactable 抽象**: 設置・アトラクトのような「場所に紐づく操作」は
  if 分岐でなく Interactable(Pos / Range / CanInteract / Interact)に一般化。
  入力は単一の `Interact`(F)で、**範囲内で発動可能な最寄りの1つだけが反応**する。
  宝箱・レバー・回復装置など今後のオブジェクトは実装1個の追加で乗る

### キャラ切り替えとスキル

- スキルは **E キー**で発動。**爆心はレティクル(カーソル)位置**。
  射程を超える指定はその方向の射程上限にクランプ。照準点を持たないデバイス
  (ゲームパッド)は AimPoint が null になり、向いている方向の射程いっぱいへフォールバック。
  発動はドッジ中不可・移動と両立。スキル命中は命中統計に数えない(KillCount は共通)
- 切り替えは**直接指定**: **1 キー=アタッカー、2 キー=デバッファー**(トグルではない。
  3人目は 3 キーで拡張)。切り替えクールダウン 30 tick。操作中キャラの再指定は不発扱い
- **スキルクールダウンはキャラごとに独立**(切り替えの存在意義)
- バランス値はキャラ単位の `CharacterConfig`(スキル CD・射程・半径・効果量)。
  デバフ倍率は付与時点のデバッファー設定値を保持(付与後に切り替えても変わらない)
- コンボの物差し: デバフ(被ダメージ2倍)→切り替え→大技(3)= 6。
  雑魚(HP 3)は大技単発、強敵は要コンボで削る
- デバフは足止めではなくダメージ増幅(足止め系は敵の攻撃パターン実装後に検討)

### 向きと射撃

**向きを決めるのはエイム入力だけで、移動は一切関与しない**(CS2D / TPS 共通、2026-07-25)。
人間操作ではマウスルックの yaw が AimDir。A を押せば右を向いたまま左へストレイフする。

- Logic (`BattleLogic.Aim`) は「`AimDir` があればその方向、無ければ**前回を維持**」の一本
- エイム入力の出どころは入力デバイスごとに Godot 層が決める:
  - マウス(TPS): **マウスルックの水平 yaw**を AimDir に送る。スキル爆心はカメラ中心レイと
    床(Y=0)の交点を AimPoint にする
  - ゲームパッド(未実装): 右スティックが倒れている間はその方向
  - エージェントの `tick` コマンド: `aimx`/`aimy` 未指定なら零 = 向きは維持。
    移動トークン(left/right/up/down)は**ワールド絶対**(カメラ相対にしない)
- **構え(右クリック)** は向きに影響しない。担当はカメラ寄りと FOV 絞り(ADS)。
  将来の精密射撃ペナルティは未実装
- 画面中央にクロスヘアを常時表示(ポーズ中は隠す)

### 3D 表示とボクセル(2026-07-29)

- Godot 層は `Node3D`。カメラは肩越し TPS。論理 tick / State / ミッションループは不変
- モデル: `art/*.voxel.txt` → `tools/voxcee` で GLB 化 → 実行時 `GltfDocument` ロード
  (attacker / debuffer / mob / boss / floor / wall / turret)
- `ui/hud` は `PlayerModelCharacter` / `AdsActive` / `CrosshairVisible` を公開
  (2D 時代の歩行シート列・向きフィールドは撤去)

### カメラとヒット演出

- カメラはプレイヤー背後+肩オフセット。構え中は距離と FOV を絞る
- ヒットフィードバック: ヒットマーカー(トーラス)、2〜6 フレームのヒットストップ。
  演出タイマーは論理 tick に同期(D-079)
- ロジックが **その tick の出来事(BattleEvent)を公開**し、Godot 層が音・演出へ翻訳する

### 操作まとめ

| 操作 | キー | tick トークン |
|---|---|---|
| 移動(人間=カメラ相対 / エージェント=ワールド絶対) | WASD / 矢印 | left/right/up/down |
| 射撃 | 左クリック / Z / J | fire(+aimx/aimy) |
| 向き(マウスルック) | マウス移動 | aimx/aimy |
| 構え(ADS) | 右クリック保持 | — |
| ドッジ | Space(移動入力必須) | dodge |
| スプリント | 左 Shift | sprint |
| スキル | E | skill(+skillx/skilly) |
| キャラ切り替え | 1 / 2 | char1 / char2 |
| インタラクト(設置・アトラクト) | F | interact |

### プレイヤースプライト(2D 時代・参考)

2D 見下ろし時代の歩行シート仕様。3D TPS 化後は実行時に使わないが、
`art/*.sprite.txt` は資産として残している。

- `art/<キャラ名>.sprite.txt` は 48x48 の歩行シート(16x16 × 3列 × 3行)

### UI(2026-07-18)

- ストレッチ不使用。下部 96px の UI バー + 左上ミッションガイド + 中央クロスヘア
- **既定ウィンドウは 1280x816**
- **Esc ポーズメニュー**: 再開 / はじめから / 中断(無効) / ゲーム終了。
  `Paused` を State 公開(D-076)。マウスは Captured↔Visible を切替
- **UI の見た目は `ui/hud` State で公開**

### ステージ定義(ダンジョン形状と敵配置、2026-07-18)

ダンジョンの形状と配置は `StageDefinition`(Logic 層)に集約し、`BattleConfig` には持たない
(Config はバランス値、Stage は空間、の分担)。

- **形状は正方形セルのグリッド**(1セル = 40 ワールド単位)。`'#'` が壁、その他は床。
  **グリッド範囲外は壁扱い**なので外周を壁で囲む必要はない
- **記述形式は ASCII マップ**(`StageMap.Parse`)。1文字=1セル:
  `#`=壁 / `.`=床 / `P`=プレイヤー初期位置(必須・1) / `M`=雑魚(0個以上) /
  `B`=強敵の出現ポイント(必須・1) / `T`=タレットスロット(必須・1)。
  マーカーは床扱いで、位置はセル中心。不正(行長不揃い・未知文字・必須マーカーの過不足)は
  `StageMapException`。同梱ステージは `Stages`(Room1)
- テスト・手続き生成は `StageDefinition` を**直接構築**できる(配置は任意の float 座標を取れる)
- **壁との衝突は Logic 層の自前判定**: プレイヤー・ドッジ・強敵は軸分離の壁スライド
  (塞がれた軸だけ壁面で止まる)、弾は壁セルに入ると消える。経路探索は無く、
  強敵は壁に引っかかる(敵 AI 再設計時の課題)
- 雑魚は複数配置でき、**全滅でエリア制圧**

### 検証用 State の粒度(2026-07-25)

`game/messbreak` は敵とステージ形状を**実体単位**で公開する(D-078)。単数フィールドで
1体分だけ見せる形はステージ定義の導入で破綻したため撤去した。

- `Enemies` … 生存している敵の配列 `{Id, Kind, Hp, X, Y, DebuffTicks}`。
  `Id` はフレームを跨いで安定(GUIDELINE 3.4)。撃破された敵は配列から消えるので、
  **雑魚の全滅は `Kind=Mob` の不在**で判定できる。強敵も同じ配列に入る
- `StageRows` / `TileSize` … ステージ形状(ASCII マップそのまま)とセル1辺の長さ。
  敵・プレイヤーのワールド座標をセルに対応付けられるので、壁との位置関係を State だけで検証できる
- 初期の雑魚数は State から直接は読めない(消えるため)。必要なら `StageRows` の `'M'` を数える

## 縦切りの歩み(要約)

- **縦切り1(2026-07-16)**: 部屋1つ+敵1種(FSM)+近接攻撃+勝敗判定。
  その後のツインスティック化で近接と敵 FSM は廃止。
  **敵の攻撃パターンは「当たる感」検証が済んだ現在、再設計して戻す予定**
- **縦切り2(2026-07-16〜17)**: ツインスティック化(エイム分離+射撃)→ スキル1個
  (クールダウン+範囲ダメージ)→ キャラ切り替え+デバフコンボ。
  途中、「当てるのが難しい」対策としてテストシーンを射撃場(リスポーンする的)にし、
  エイムアシスト・判定調整・命中統計・カメラ・ヒット演出を導入
  (的は縦切り3-1 で敵エンティティに置き換えて廃止)
- **縦切り3-1(2026-07-18)**: 制圧→設置→アトラクト→強敵撃破の最小ループ。
  headless E2E でフルループ(タレット弾へのデバフ倍率含む)を確認済み
- **操作系の CS2D 化(2026-07-25)**: 向きの規則を「常にカーソル方向」へ一本化し、
  構え/非構えで向きが変わる二面性を廃止(上記「向きと射撃」)。
  参照した先達は **CS2D**(2D 見下ろしの Counter-Strike)。同作は常時カーソル向きで
  向きのモードを持たず、規則が一本で済む。ドッジ・スプリント・スキルは CS2D に無い層だが、
  MessBreak のコアなので残した
- **3D TPS 化(2026-07-29)**: Godot 層を Node3D + 肩越しカメラ + voxcee GLB に置換。
  Logic / ミッションループ / State パスは維持。人間 WASD のみカメラ相対化

次の候補: 強敵の攻撃+プレイヤー HP(緊張の導入)、部屋の複数化(前進のリズム)、
設置物のバリエーション(壁・デコイ等、準備の選択肢)、ボクセルアニメ(歩行)。
